# 账号切换与账号池同步修复（1.0.9）

2026-10-15 的现场检查发现：界面预期为国内 1 个、国际 2 个账号，失败时服务接口却只返回 1 个国际账号，且它的 Step-5-Preview 被限制到次日重置。重新启动并读取文件后，服务接口恢复为 2 个国际账号。用户确认没有删除或重新登录账号。

因此，不能把此次错误简单归因为“两个账号的免费额度都用完”。现场已确认运行状态不一致；下述缺陷可以复现，但无法仅凭现有日志认定它们是本次不一致的唯一原因。

## 修复

- 账号文件缓存由单一修改时间，改为同时检查修改时间、变更时间、大小与文件身份。外部同步或导入保留原修改时间，也能发现新账号。
- 延迟保存前重新核对文件；文件已被外部替换时，丢弃旧的保存回调，避免把新增账号覆盖回去。
- 账号添加、删除、启停及状态变更，写入成功后才提交内存变化；写入失败不再造成“磁盘有两个、运行中少一个”的假状态。
- 登录账号页增加「重新读取账号」。它读取本机已保存的账号，不需要重新授权，也不会清除模型额度限制。
- 额度全部受限时，错误列出实际检查的账号数量、各账号状态及重置时间。三种协议返回 `insufficient_quota` 类型、`model_quota_exhausted` 错误码和 `retryable:false`；客户端是否遵守此标志取决于其实现。

切换仍遵守原有规则和每次尝试账号数，不会把其他模型替换进当前任务。严格免费模式下，未知或收费的备用渠道仍会被拒绝。

## 验证

在旧版独立临时数据中，新增第二账号并保留修改时间后，只能读到一个；旧延迟保存还会把文件覆盖回一个。修复后的回归测试能稳定保留两个账号。另验证写入失败时账号不被悄悄删除或禁用。

444 项后端测试通过；界面操作及打包桌面检查另外验证。现场使用账号资料接口确认账号数量，不发送真实模型测试请求，不把“账号已识别”等同于“免费额度尚有剩余”。
