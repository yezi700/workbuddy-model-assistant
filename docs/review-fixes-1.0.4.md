# 全局审查修复（1.0.4）

本版本修复全局代码审查中发现的问题，不新增功能。下列问题在 1.0.3 中均可复现：同一套回归测试在 1.0.3 上只有 8/26 项通过。

## 协议兼容

- **Anthropic 流式工具调用**：工具参数的增量类型由 `partial_json` 改为规范要求的 `input_json_delta`。旧类型会被按规范解析的 SDK（Claude Code 等）忽略，工具最终以空参数被调用。`tool_use` 起始块补上 `input: {}`。如果工具调用之后还有正文，正文会另开一个文本块，不再写进工具块。
- **Responses 流式**（Codex）：
  - 上游报错时，只发送带错误信息的 `response.failed`，不再接着发送 `response.completed`；流中途出现异常也会补发 `failed`。
  - 每个输出项在开始时就分配自己的 `output_index`。修复前，“推理后直接调用工具”这一推理模型最常见的顺序会让推理项和第一个工具项共用同一个索引。
  - 推理项和正文在工具项开始之前收尾；`completed` 中包含全部已收尾的输出项。
- **Responses 的 `stream` 缺省值**改为 `false`，与 OpenAI 规范一致。修复前，不传 `stream` 的 SDK 会收到 SSE。

## 账号池与上游

- 判断“额度不足”时排除上下文超长。修复前，`exceed` 关键词会把 `context_length_exceeded` 误判为额度耗尽，一次超长请求就能把池里所有账号标记为耗尽 6 小时。
- 只有鉴权失败、额度不足和上游 5xx 才会换账号。修复前，参数错误、模型不存在等 4xx 换哪个账号结果都一样，却照样逐个换号，还给每个账号记一次失败冷却。
- 输入超长且无法继续压缩时，上游错误原文会照常返回给客户端。修复前，客户端只能收到空的 “上游 HTTP 400：”。

## 数据可靠性

- `/admin/shutdown`、控制台的停止服务，以及 SIGINT/SIGTERM，退出前都会写入尚未落盘的用量统计和号池状态。桌面版每次停止、重启、退出都会走这条路径，修复前最近几秒的数据会丢失。
- 配置、号池、用量、凭证改为原子写入（先写临时文件，再 rename）。
- 路由规则中某一条无效时，只丢弃这一条并记录问题，`routing.fallbackMode` 无效时回退为 `off`。修复前这两种情况都会让服务无法启动。

## 安全

- 控制台账号区的按钮改为 `data-*` 属性加事件委托，`esc()` 也会转义单引号。修复前，账号名会被拼进 `onclick` 字符串：带单引号的名字会让按钮失效，构造好的名字（包括上游返回的昵称）还可以在控制台中执行脚本。

## 桌面端与性能

- 导入旧配置或修改端口时，如果中途出错，会自动重新启动代理服务；修复前服务会一直停着。
- `desktop.log` 超过 5MB 时转存为 `desktop.log.1`。
- 页面不可见（收进托盘）时暂停状态轮询；首页余额缓存 60 秒；日志只在“排查问题”页拉取，页面上最多保留 1000 行。
- 授权登录同一时间只保留一条轮询，最多等待 10 分钟。
- 重复出现的鉴权失败、来源拒绝、限流告警每分钟只记录一条，并附上被省略的次数。实测中，浏览器里遗留的旧控制台标签页每 2 秒会产生一条告警。
- 从模型表选择模型后，首页和模型表能正确标出当前模型。桌面版的错误提示改为引导用户到“登录账号”页登录。配置损坏或导入出错时，提示中会包含文件路径。
- 删除了从未被调用、且本身有 bug 的 `openWithFallback`。

## 验证

- `npm test`：423 项测试通过，其中新增 `test/review-fixes.test.mjs`（13 项），使用本地模拟上游做端到端验证。
- Windows 打包版通过 17 项桌面冒烟检查。
- 在浏览器中实测控制台：使用注入用的账号名时脚本不会执行；改名、禁用、切换模型、日志等功能正常。
- 未发起真实的模型调用。

## 未改动的建议

- 构建时可以通过 `electronFuses` 关闭 `RunAsNode`、`EnableNodeOptionsEnvironmentVariable`、`EnableNodeCliInspectArguments` 这三个 fuse。
- 429 目前一律视为额度耗尽，账号会因此休息 6 小时。如果上游的 429 只是短时限流，可以考虑缩短这个时间。
- 控制台中的 `promptTokenLogin`（调用不存在的 `/login/token`）是早期 DeepSeek 方案留下的死代码。
- 从 MSIX 打包的应用（例如 Codex 桌面版）中启动本程序时，Windows 会把 `%APPDATA%` 的写入重定向到该应用的包目录（`%LOCALAPPDATA%\Packages\<包名>\LocalCache\Roaming\…`）。这时的数据与从开始菜单启动时的数据是两份。
